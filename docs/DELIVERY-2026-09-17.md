# Orbitlab improvement delivery — 2026-09-17

Branch `fable-improvements` in `Orbitlab/Claude code version` (baseline: GitHub `main` at de6ae33).
Work was orchestrated by Claude Fable 5.1 as chief engineer with Opus and Sonnet agents doing the
implementation, every change adversarially reviewed by an independent Opus reviewer, and the
whole branch reviewed twice at the end.

## What was done

1. **Audit and comparison.** Both codebases (the Codex version and this one) were audited by
   six-dimension workflows with two verifiers per finding (`docs/AUDIT-2026-09-16.md`, 42 items).
   This codebase was chosen as the main line; the Codex version stays as the design reference.
2. **Wave 1 — physics, graphics, fleet.** Robust default guidance (every vehicle flies without
   auto-tune; fleet acceptance suite with measured exclusions), per-site launch complexes and
   terrain, vehicle liveries and engine layouts, layered plumes, ground smoke, sun/altitude sky,
   cinematic cameras, frame-driven rendering, plus Vega-C, Long March 2D, Long March 3B/E,
   H-IIA 202 and the Jiuquan, Taiyuan and Xichang sites.
3. **Wave 2 — replay, design, follow-ups.** Recorded flight with a scrubbable timeline and a
   real-time event bar (piecewise axis so the ascent keeps most of the bar), live/replay modes,
   Codex-style control-room design blended with the engineering panels, phase narration, camera
   sequence per phase, physics & sources dialog, pre-flight feasibility verdict, plus physics,
   render and data fixes from the audit.
4. **Wave 3 — integration, languages, tools, docs.** Telemetry rewinds with the cursor,
   onboard porthole, Russian and Thai terminology review with parity tests, WebMCP tools
   (`src/mcp.ts`), README and `docs/USER-GUIDE.md`, night-launch pad lighting, break-up effect,
   release review fixes (localized event names, site range-safety corridor, capability verdict).
5. **Wave 4 — the parallel quality pass, merged by hand.** While this branch was being built, a
   separate session pushed four commits to `origin/main` (a791ea3, b841fcc, 5a29e66, 6748ea1)
   against the *old* architecture; the merge was recorded with our tree (a108eca), so nothing of
   theirs was in the working tree. Every hunk was then re-evaluated against this codebase and
   ported where it still added something:
   - **Rendering:** a post-processing chain (4× MSAA target → UnrealBloom → tone-mapping output
     pass) with a Glow toggle in the viewport tools and an automatic cut-out when the frame rate
     cannot afford it; relief-mapped Earth from `public/textures/earth_normal_2048.jpg`.
   - **Cameras:** the pointer-capture guard (a press on a control inside the viewport no longer
     starts a camera drag), the primary-button check, two-finger pinch moved into
     `CameraController` with a re-seeded drag baseline, and a parallel-transported reference axis
     for the space view so it no longer flips over the poles.
   - **Physics:** the orbital plane is established `T_PLANE` = 200 s after liftoff (measured: the
     RAAN residual falls from 0.63–0.94° to under 0.11°); burns ignite only once the attitude is
     aligned; booster recovery sized per vehicle (entry burn to 1.4 km/s, hoverslam at
     thrust/weight 3); premature separation now breaks up the stage that is burning; the
     telemetry buffer is bounded; `planMission` defaults the payload to the selected spacecraft.
   - **UI:** the map's terminator (the old `atan2` form misclassified 78–96 % of the map for a
     southern solar declination, i.e. half the year), landed debris pinned to their ground
     position, an incrementally built ground track, a chart axis that respects a declared floor,
     `{pe} × {ap}` apsis order in all three languages, and a `hud.note.noLiftoff` string.
   Their CPU particle systems, procedural stage skins, chase-camera smoothing, onboard framing,
   HUD/panel/i18n rework and auto-tune-on-launch were **superseded** by this branch's own work or
   **rejected** for conflicting with the frame-driven contract; the accompanying report lists each
   one with its reason.

## How to publish

The branch is committed locally and not pushed. Review it, then:

```bash
git push -u origin fable-improvements
```

Open a pull request into `main`; the GitHub Pages workflow deploys on merge.

## Known limitations (documented in docs/PHYSICS.md and docs/RELEASE-REVIEW-2.md)

- Falcon 9 max Q is marked about 15 s early because of the throttle-bucket data; moving it
  shifts MECO and fairing out of their windows, so it was left and pinned by a test.
- Break-up shows a fireball and smoke but does not spawn physical debris (the simulation stops at
  loss of vehicle).
- The secondary HUD readouts hide at small viewport heights so the vehicle stays visible.
- One fleet row (PSLV-XL to GTO at 50 % payload) is beyond capability only because of losses a
  static verdict cannot see; it is pinned as an explicit exception.
