- **Why the worker settings cannot do it.** Vite bundles each worker by a build of its own (`bundleWorkerEntry` in the installed vite), so `worker.format` and the worker's own chunking options split a worker only inside its own bundle. A physics chunk asked for through the worker options came out as eight different chunks, one per worker, and the precache grew to 15,202.3 kB.
- **Route 1.** A build-only plugin turns each `new URL('./x.worker.ts', import.meta.url)` into an entry chunk of the main build (`emitFile`), so the bundler shares code between workers and with the page as it does for any two entries. The twelve `new Worker(` sites, every `*-job.ts`, every `*.worker.ts` and every message are unchanged. The patch is in the appendix.
- **Route 2** adds a chunk group for `src/physics`. It saves 3.5 kB more, and every worker then evaluates the whole physics core: the lifetime worker loads 629.2 kB where route 1 gives it 49.7. On the first attempt the group swallowed the worker entries themselves: four of them became the same empty file, and the page would have run every worker's message handler. The group needs a pattern that excludes `*.worker.ts`.
- **Why the budget fails although the total falls.** `other chunks` comes to 2,240.0 against a ceiling of 772.0, because the shared code is now in chunks with new names; and `catalog-*.js`, `i18n-*.js`, `lesson-file-*.js` and `preload-helper-*.js` no longer exist under those names, which the script reports as a failure. The chunking of the page's own graph changed when the workers joined it.
- **What was exercised, once per route, on the built app in Chromium:** the page loads and starts its flight worker as a module worker with no error; each of the twelve worker files starts as a module worker with no error event; the lifetime worker answers one request, with the same number in both routes. No console error, no failed request.
- **Not measured.** The same request against the baseline build; any job through its own wrapper or the interface; any other worker's answer; the development server; offline use from the precache; the site's sub-path on Pages; any browser but Chromium; which modules each shared chunk holds.

## 2. Three decisions of the owner

Decided on 2026-11-28: the owner took the recommendation on all three ([DECISIONS](../../DECISIONS.md), "Decided 2026-11-28", the row on T-1). The text below is kept as it was put to the owner; "Recommended" now reads "decided".

**1. `budgets.json` in the same pull request.** S09's constraint 9 says a pull request of EQ that shrinks a chunk does not edit `budgets.json`; the ceilings are lowered later, in a ratchet pull request. That cannot hold here: the gate fails on names that no longer exist and on `other chunks`. The file's own rule is that a ceiling is raised only with its reason written beside it, and D-38 makes a raise the owner's.
- *Recommended:* the pull request that changes the build also rewrites the groups of `budgets.json` to the new chunk names, with **every** ceiling set at the measured size plus the margin the file uses today, `precache code` and `precache` lowered by what was freed, and one named exception: `other chunks` goes up because it now holds the shared code that twelve worker groups held before. The owner signs the table of old and new ceilings before the merge.
- *Otherwise:* keep the names by forcing the old chunking, if that is possible at all; not measured, and it would work against the sharing.

**2. How much of FX-4 stays in T-1.** The owner's "4.ก" authorized "EQ-8 and the rest of FX-4". The measurement shows the size comes from the build alone. FX-4's shared runner serves other ends: one error path for a worker that fails to load, and the warm worker of M-BUILD-030. Its steps 2 to 4 change messages the user reads, in three languages.
- *Recommended:* T-1 is EQ-8's first pull request (M-PLATFORM-033) and no more. Two of its acceptance lines lean on the runner and are met without it or carried: "a failed chunk import goes to the existing error path" is checked on today's wrappers as they are (Task B, Step 5), and if a wrapper shows an empty message for a failed load, that is recorded and left to FX-4. M-BUILD-030 and the rest of FX-4 go back to their own lane, outside this track.
- *Otherwise:* T-1 keeps all of FX-4; its user-facing messages come to the owner before they merge, and T-1 becomes several pull requests.

**3. A browser without module workers.** The owner's D-40 names Chrome and Edge 94, Safari 16.4 and Firefox 114. The compatibility tables give module workers from Chrome 80, Safari 15 and Firefox 114, so every supported browser has them, and Firefox 114 is the first Firefox that does. Today's worker bundles would still start in an older browser; after T-1 they would not.
- *Recommended:* no fallback is built, since no supported browser needs one; S09's guard asks for one only "if D-40 still has to support a browser without module workers". The report says plainly that browsers below D-40 lose the workers.
- *Otherwise:* a second, self-contained build of the workers kept for such browsers, which gives back most of the saving.

A fourth point is not a decision but the owner should see it: the first load asks for 33 files where it asked for 8 (13.4 kB more in total). The files are small and fetched together, and the service worker precaches them; the time to first use was not measured. Task B measures it against the baseline.

## 5. What could make this plan wrong

## Appendix: the scratch patch of route 1

On `8a8cb9d`; it built and passed the checks of §1. It is the starting point of Task B, Step 1, not reviewed code.

```ts
/** Each `new Worker(new URL('./x.worker.ts', import.meta.url), …)` becomes an entry chunk of the main build. */
function sharedWorkersPlugin(): Plugin {
  const re = /new URL\(\s*'(\.\/[\w.-]+\.worker\.ts)'\s*,\s*import\.meta\.url\s*\)/g;
  return {
    name: 'orbitlab-shared-workers',
    apply: 'build',
    enforce: 'pre',
    async transform(code, id) {
      if (!/\.ts$/.test(id) || !code.includes('.worker.ts')) return null;
      let out = code;
      for (const m of [...code.matchAll(re)]) {
        const resolved = await this.resolve(m[1], id);
        if (!resolved) continue;
        const ref = this.emitFile({ type: 'chunk', id: resolved.id, name: m[1].slice(2, -3), preserveSignature: false });
        out = out.replace(m[0], `import.meta.ROLLUP_FILE_URL_${ref}`);
      }
      return out === code ? null : { code: out, map: null };
    },
  };
}
// and in defineConfig: plugins: [sharedWorkersPlugin(), htmlCommentsPlugin(), pwaPlugin()]
```
