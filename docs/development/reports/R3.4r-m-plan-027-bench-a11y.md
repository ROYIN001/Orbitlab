## What was wrong (on `7b2a3cb`, live since `09cc2f5`)

1. **Stacked / Apart** on the Engineer rocket bench (`engineer-level.ts` `renderPreview`): pressing either button from the keyboard redrew the preview. The redraw replaced the buttons, so the keyboard fell to the page.
2. **Deployed / Stowed** on the satellite bench (`satellite-bench.ts`): the same problem.
3. **"Show the part"** (a readiness row, `showPart`) scrolled the drawing into view with a smooth scroll, even when the reader had asked for reduced motion.
4. **Strap-on names.** A strap-on group's label on the bench drawing had the accessible name "Strap-ons ×4". Watch and Explore name the same label "Strap-ons ×4: Blok B/V/G/D boosters". A screen reader therefore heard two names for one part.

## The fix

1. After the redraw, the keyboard goes back to the button pressed. On the rocket bench this is the `[value]`-th `.be-preview-modes .be-mode`; on the satellite bench it is `[data-k="sb:pose-…"]`.
2. `showPart` scrolls with `behavior: 'auto'` under `prefers-reduced-motion: reduce`. It uses Explore's `reducedMotion` helper, now exported, so the code is not duplicated. `build-screen.ts` already imports both modules, so no chunk changes.
3. The bench's strap-on label is named `"<role>: <booster name>"`, built as Watch and Explore build it. A missing group falls back to the role alone.

No string, no CSS, no stored format changed.
