## สิ่งที่ทำ

### A02 — ผลการบินพาไปที่ค่าที่เกี่ยวข้อง (typed, ไม่แก้แทนผู้ใช้)

- `src/ui/result-actions.ts` (pure): `resultSetting(cause, ctx)` เลือก field จาก **cause ที่ระบบ typed ไว้** ไม่อ่านข้อความแปล — failure ที่ตั้งไว้ใน setup และ **เกิดจริงก่อนจบเที่ยวบิน** (`evt.engineOut`, `evt.prematureSep`, … ที่ `t ≤ outcomeTime`) → `setup.failureMode`; `window` → `setup.launchTime`; `shape` → `setup.perigee`; `inclination` → `setup.inclination`; `fuel`/`liftoff` → `setup.payloadMass`; `target` และ `incomplete` → ไม่มีปุ่ม (ไม่เดา)
- การ์ดผลแสดง “Show the setting: <ชื่อ field>” → Engineer แสดง setup ที่พับไว้ (อ่านอย่างเดียวเพราะมีเที่ยวบินอยู่), Explore สลับไปขั้นที่มี field นั้น; เปิด `<details>` ที่ซ่อนอยู่, เลื่อนเข้าจอ, focus field (ถ้า disabled ให้ label รับ focus แทน) และ highlight 2.4 s — **ไม่เปลี่ยนค่าใด ๆ** ผลเที่ยวบินเดิมไม่ถูกแก้
- field ใน `panel.ts` มี `data-field="<labelKey>"` เพื่อหาโดย key เดียวกับที่ result ใช้

### U05 — บอกว่า mission มาจากไหน

- `src/ui/mission-source.ts` (pure): eyebrow เหนือชื่อ mission เป็น “MISSION · catalogue rocket / your design / lesson / from Watch / first-launch template / a copy to try” ตาม origin ของ workspace (A1 เดิม), lesson ที่เปิดอยู่ และ custom vehicle/satellite

### A01 — Home “Try a launch yourself”

- ปุ่มใหม่บนหน้าแรกเปิด Explore บน **first-launch template** (`FIRST_LAUNCH` = quick start LEO: Falcon 9 จาก Cape, CubeSat rideshare 1,000 kg) พร้อม note ที่บอกสิ่งที่ใช้ (ยาน, ฐาน, payload, วงโคจร, ความเอียงที่จะเล็งจริงจาก `resolveTarget`)
- origin ใหม่ `template` ใน `WorkspaceMission`: เหมือน mission ของ viewer คือ **ไม่ถูกเก็บจนกว่าจะถูกแก้** → การเปิด route ไม่ทับ mission ที่บันทึกไว้; ต่างจาก viewer ตรงที่เข้า workspace แล้ว **ไม่ถูกสลับกลับ** เป็น mission ที่บันทึกไว้ (ผู้ใช้ขอ template เอง)
- ถ้ามี mission ที่บันทึกไว้ note บอกว่า “Your saved mission is kept until you change this one.” และมี “Back to my mission”; การแก้ครั้งแรกทำให้ template เป็นของผู้ใช้ (note หาย, eyebrow เป็น catalogue rocket, ถูกเก็บ)

### Watch → สำเนาไว้ทดลอง

- การ์ดจบของ Watch มี “Try this launch yourself” → Explore บน **สำเนาใหม่** ของ settings (`watchMissionSettings` สร้าง object ใหม่จาก definition ทุกครั้ง จึงแก้ demo ไม่ได้) ใช้ทาง template เดียวกัน; note บอก “The launch in Watch stays as it is.” และ eyebrow “a copy to try”; failure ของ launch (เช่น pad fire ของ Soyuz T-10) ติดมาในสำเนาตามจริง

### compact mission context — ขั้นของ mission

- `src/ui/mission-steps.ts` (pure): Build › Check › Launch › Result › Orbit ใต้ชื่อ mission ที่ Explore/Engineer อ่านจาก lifecycle stage (R2.1), ความถูกต้องของ setup และ `handoffAvailable` ของ frame ที่แสดง — current มีหนึ่งขั้นเสมอ; Orbit ขีดฆ่าเมื่อเที่ยวบินจบนอกวงโคจร
- ชิปที่กดได้: Build → Build section, Check → verdict ใน setup (ก่อนปล่อย), Result → การ์ดผล (focus), Orbit → Continue in Orbit; Launch คือหน้าที่อยู่
- แถบชื่อ mission ปล่อย pointer ผ่านไปที่ฉากเพื่อหมุนกล้อง — ชิปรับ pointer เอง (`pointer-events: auto` เฉพาะปุ่ม)
- Docking ยังไม่อยู่ในสายขั้น (เพิ่มเมื่อ R5 ทำ Docking ใน Orbit ได้)
