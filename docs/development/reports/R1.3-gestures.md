## Reproduced problem

The Launch camera listened to the entire `#viewport`, which also contains the Build and Orbit pages. A wheel over Build text reached the covered Launch camera; Orbit canvas wheel zoomed both cameras because its event bubbled after `preventDefault`.

The separate baseline production build, before these gesture changes, reproduced at 1024 × 700 with actual Chromium mouse wheel input:

| Input | Before | After |
| --- | --- | --- |
| Build Engineer text, wheel +450 px | Build scrollTop 0; hidden Launch zoom 1.05 | Build scrollTop 0; hidden Launch zoom 1.176 |
| Orbit 3-D canvas, wheel +120 px | Orbit distance 21.074; hidden Launch zoom 1.176 | Orbit distance 26.791; hidden Launch zoom 1.317 |

The Build page had 2273 px of content in a 640 px scrolling viewport. No uncaught page errors occurred in this reproducer. The observed hidden camera changes were caused by gesture routing, rather than a page with nothing to scroll.

## Completed implementation

- `src/main.ts` now attaches Launch input to its own `#gl` canvas with `isActive: () => !this.sceneCovered`. Build, Orbit and covering Home pages retain their own gestures.
- `src/style.css` places `touch-action: none` on `#gl` instead of its shared `.viewport` ancestor. Native touch panning is consequently available to Build/Orbit text; the Orbit 3-D canvas keeps its existing dedicated `touch-action: none`.
- `src/render/gestures.ts` centralizes surface ownership and wheel normalization. Pixel, line and page `deltaMode` values are handled, small trackpad deltas remain small, coarse per-event zoom is bounded, and Ctrl/Meta wheel remains available to browser zoom. Horizontal-only/zero/nonfinite wheel input is not captured.
- `src/render/cameras.ts` accepts an optional activation policy while preserving `attach(el)` compatibility. Covered Launch gestures do not zoom or rotate the scene. Captured drags are cleared on inactive input and existing pointer-cancel/lost-capture handling remains in place.
- `src/render/orbit-view.ts` owns wheel input only on its visible canvas and stops propagation after handling it. Secondary mouse buttons do not start a drag; pointer capture failures/cancellation are handled; focused canvas keyboard rotation/zoom remains available and does not intercept browser modifier shortcuts.
- `index.html` and `src/main.ts` remove `btn-reset-cam` and its event binding. The internal camera `reset()` API remains available for opening/framing missions; mission reset and Orbit framing controls remain separate functions.

## Addendum — opaque lessons page owns the scene

An independent production probe on Chromium **151.0.7922.173**, render scale 0.5, measured **2790 real `#gl` WebGL draw calls in 5 seconds** while the opaque lesson catalog covered the Launch canvas: 540 `drawArrays`, 1944 `drawElements` and 306 `drawElementsInstanced`. The probe confirmed the topmost elements at the viewport were inside `.lessons-page`, fonts were loaded and no uncaught page errors occurred. Evidence for that baseline is `/tmp/orbitlab-r1-hidden-scene-probe.json` (build stamp `f2d7e48`, built 2026-10-03T04:53:38.199Z; probe started 04:58:55.094Z). This measurement establishes unnecessary covered-scene rendering; it does not establish the cause of every prior browser timeout.

The integration owner extended `main.ts`'s `sceneCovered` predicate to include `document.body.dataset.lessonsPage`, preserving simulation updates while skipping rendering and camera input on covered lesson pages. The production build has been refreshed for the regression gate.

`gesture-ownership.mjs` now independently observes the actual Launch WebGL context over four animation frames, restores every observed method afterwards, and requires **visible draws > 0 → covered catalog draws = 0 → resumed visible draws > 0**. It also verifies the catalog is topmost over `#gl`. These positive samples prevent a stopped/broken renderer from producing a false pass. All existing wheel/touch/keyboard/canvas assertions remain, and the journey timeout stays 180 seconds.

Final gate: `node tests/browser/run.mjs --dist dist --shots /tmp/orbitlab-r1-final-gesture-shots gesture-ownership` passed **1/1 journeys**, 30.3 seconds for the journey / 32.2 seconds total, on refreshed production dist manifest `0880ee57146283`. The original gesture assertions remained green, and the independently observed real Launch draw calls were **612 visible → 0 covered → 612 resumed** over four animation frames per sample. The opaque catalog was confirmed topmost and no uncaught page errors were reported. JavaScript syntax and whitespace checks passed; the runner exited zero and closed its browser/server before releasing the exclusive Chromium slot. No measured speed-up percentage or resolution of all CI timeouts is claimed.
