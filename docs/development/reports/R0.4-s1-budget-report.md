## What was missing, on `4de951f`

`scripts/bundle-budget.mjs` reported raw sizes only. Three things were missing:

- **Compressed sizes.** The script did not show what a learner actually downloads over the network.
- **The first-visit set.** No group added up the files that load before the app runs.
- **The textures.** The Earth textures were hidden inside `precache code`.

The plan row asks for gzip/brotli columns, an initial-load group and a texture group "so startup bytes ratchet like code bytes". This step adds the report only. Ceilings for these groups are the owner's decision under D-38, so `budgets.json` is not touched.

## What changed

After the gate's table and before the build-log line, the script now prints a report-only block:

```

group                           files   raw kB  gzip kB  brotli kB
------------------------------  -----  -------  -------  ---------
index-*.js                          1   2633.3    815.8      655.2
index-*.css                         1    177.0     34.3       29.2
…   (every group of the gate's table, in its order)
precache                           68  15812.5   7654.4     7021.3
precache code                      65  14693.3   7476.8     6888.3
precache data/                      3   1119.2    177.6      133.0
i18n-*.js                           1   1724.7    416.5      301.4
lesson-file-*.js                    1    345.1    110.3       93.5

(initial load: index.html, assets/index-DShKegw7.js, assets/i18n-CWrk2N1l.js, assets/lesson-file-D-lA8e66.js, assets/download-DOxmd5KI.js, assets/catalog-WF3u0kRA.js, assets/index-5VG9jJdm.css)
```

These numbers come from the build of `4de951f`.

- **gzip and brotli.** Each file is compressed on its own, at each format's maximum level (gzip level 9, brotli quality 11), the way a server sends it. JPEG, PNG and other formats that are already compressed count at their raw size, because servers send them as they are. That is why the textures row shows the same number three times.
- **`initial load`.** This group is computed, not a fixed list. It is `dist/index.html` plus every `<script src>` and every `<link rel=modulepreload|preload|stylesheet>` in that file. Comments, inline scripts, `data:` URLs, other origins, the manifest and the icons are left out. Today the page also preloads `download-*.js` (2.6 kB), which the plan row did not name. The group follows the page automatically when Vite changes what the page preloads.
- **`textures`.** Every file under `dist/textures/`, whether or not it is precached.
- **Missing files and errors.** A linked file that is missing from `dist/` is named and not counted. A group with no files reads `absent`. If measuring fails, the script prints a line and carries on. The report never changes the exit code.
- **Speed.** Compression runs on Node's libuv thread pool. The check takes about 6 s on the real dist. Measured: brotli q11 one file at a time took 21 s; quality 9 would take under 1 s but gives 11 % larger numbers.
- **Code changes.** Two small refactors, with identical output:
  - `assetFiles()` takes an optional pattern, so the texture group can list every file.
  - The gate's table printing moved into `printTable()`, which the report also uses.

  `initialLoad(html)` is exported for the tests. Source change: `scripts/bundle-budget.mjs` +121/−14.

### The gate is byte-identical

The old script (`4de951f`) and the new one were run on the same inputs. With the report block removed from the new output, the results matched exactly:

- The real dist with its build log: same stdout and the same exit code 0.
- All 13 fixture runs of `tests/verification/bundle-budget.test.mjs`: the same exit code, the same stderr and the same stdout in every run. 11 of the runs print the report. The 2 runs that stop early on a bad `budgets.json` print no report, as before.
- An unparsable `budgets.json`: exit 1 in both versions.

The new test "the gate is unchanged" pins this. It holds the gate's stdout and stderr recorded from `4de951f` for a fixture that has rows for all of these: ok, FAIL overrun, absent, no budget, a data warning and the build-log failure.

### Note for a future ceiling (owner decision, not made here)

gzip and brotli sizes change slightly from one commit to the next even when the source does not change. The build writes the commit SHA into `index-*.js` and `recheck.worker-*.js`. A rebuild of identical source at `a10a222` gave these brotli changes:

- `index-*.js`: 655.2 → 655.6 kB
- `recheck.worker-*.js`: 235.9 → 236.0 kB
- `initial load`: 1123.4 → 1123.8 kB

gzip and raw did not change. A ceiling on the compressed columns would need about 1 kB of slack, or a build with a fixed SHA.

## Tests

Tests came first, in a separate commit (`a10a222`). The new file is `tests/verification/bundle-budget-report.test.mjs`, 6 tests. Each test runs the real command on a throwaway `dist/`, except the `initialLoad` unit test:

1. **Initial load.** The fixture page has a commented-out script, a `data:` icon, the manifest, an apple-touch icon, the entry script, two module preloads, a stylesheet, a script from another origin and an inline script. The group must be exactly the page plus its 4 linked files, in page order. Its raw, gzip and brotli sums must equal `zlib`'s own per-file sizes. A lazy chunk must be left out.
2. **Per-file compression.** Every group gets gzip and brotli columns. The fixture has two identical chunks in `other chunks`, and each must count in full. That proves each file is compressed alone.
3. **Textures.** Three zero-filled images (`.jpg`, `.jpg` and a nested `.png`), one of them not precached. The group must count 3 files at raw size in all three columns.
4. **The report never fails.** A missing `textures/` directory reads `absent`. A linked stylesheet that is missing is named and not counted. The output has no `FAIL` and ends with `bundle budget: ok`.
5. **The gate is unchanged.** The stdout and stderr recorded from `4de951f` must match exactly, with the report block removed.
6. **`initialLoad()` parsing.** Single-quoted and unquoted attributes, a `>` inside an attribute value, query and hash suffixes, duplicates, `rel=preload`, a root path (`/textures/…`), and `//cdn…`, `https:` and `data:` links.

Failing on the base: the test commit `a10a222` was run against the script from `4de951f`:

- **App bundle: no change.** `src/`, `index.html`, CSS and strings are untouched. The gate's table for this branch's build matches the build of `origin/main` (`4de951f`) on every row. The deltas are 0 B for `index-*.js`, `i18n-*.js`, `index-*.css`, precache code and every other group.

## CI fix (2026-10-08)

The first CI run of #140 failed in `plan` with 78/79. The gate test ("the gate is unchanged …") ran the script with the runner's environment. On GitHub Actions, `GITHUB_ACTIONS=true` makes the gate print one more line, a `::warning title=precache data/::…` annotation (main's script, `scripts/bundle-budget.mjs:224`). That line is not in the test's expected text. The failure reproduces locally with `GITHUB_ACTIONS=true node --test tests/verification/bundle-budget-report.test.mjs` (5/6).

The test's fixture now runs the script with `GITHUB_ACTIONS` cleared, so it prints the same text on every machine. No assertion changed. After the fix the set passes 79/79 both with `GITHUB_ACTIONS=true` and without it, and `tests/bundle-budget.test.ts` passes 8/8.
