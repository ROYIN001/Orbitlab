## M-PLATFORM-001 (P1) — an unreadable selected record kept its owner lock

**What failed.** `initialize()` did `const release = await this.hold(selected), record = this.read(selected);`. When `read()` threw (truncated JSON), `this.release` was still `null`, so the catch's `this.release?.()` freed nothing: the profile's Web Lock stayed held until the page closed, and every other tab got `locked` (read-only, no rename or delete) for that profile.

**Fix.** `this.release` is assigned straight after `hold()` and before `read()`, so the existing catch releases it. The success path is unchanged (same lock, same status, same binding). The unreadable record is not touched: the tab opens visit-only (`ephemeral`, never writes), notices `invalid` and `stored-work-unavailable` are pushed and shown through the existing generic recovery notice, and the bytes stay on disk.

**Test** (`workspace-profiles.test.ts`, "M-PLATFORM-001: releases the owner lock …"): Locks double with real exclusivity; a non-legacy selected profile's record truncated by 12 characters; the first repository opens visit-only and its writes do not reach the bytes; the record is then restored while the first tab is still open, and a second repository must be `durable`.

## M-PLATFORM-002 (P1) — one failing start-up cleanup sent every profile to visit-only

**What failed.** Inside `withCatalog`, the tombstone retry (`hold` + `finishDelete` → `media.delete`) and the legacy-original cleanup (`this.read(catalog.legacyId)`) had no error handling of their own (only `media.migrate` did). A rejecting media delete or an unreadable legacy record threw out of `initialize()` and every start went to `initializeEphemeral()`: nothing the learner did was saved, on every start, while the cause persisted.

**Fix.** Each tombstone retry is contained: on failure the tombstone (and its record and media) stays for the next start and `profile-delete-pending` is pushed. The legacy cleanup is contained: on failure no original key is removed (they remain for the next start's retry) and `legacy-cleanup-pending` is pushed. Both codes show the existing generic recovery notice (`recoveryNotice` in `app-profiles.ts`, no new text). Healthy profiles then open durably.

**Tests** (`workspace-profiles.test.ts`):
- "a rejecting tombstone retry keeps the tombstone …": media double whose `delete` always rejects, legacy profile tombstoned, healthy second profile selected; two `initialize()` runs must each be `durable` on the healthy profile, keep the tombstone and the record bytes, push a notice, and save; `media.delete` is called once per attempt (3).
- "an unreadable legacy record does not send a healthy selected profile into visit-only mode": legacy record truncated, healthy profile selected → `durable`, bytes kept, notice pushed.

Before:
```

AssertionError: expected 'ephemeral' to be 'durable' // Object.is equality
 ❯ tests/workspace-profiles.test.ts:200:27
FAIL  … M-PLATFORM-002: an unreadable legacy record does not send a healthy selected profile into visit-only mode
AssertionError: expected 'ephemeral' to be 'durable' // Object.is equality
 ❯ tests/workspace-profiles.test.ts:212:25
```
After: both pass. No silent orphan media: a failed media delete leaves the tombstone, which is retried at every start, and a notice is shown.

## M-LEARNING-005 (P2) — the 1,001st numeric draft field threw

**What failed.** `rememberNumericText` threw `Numeric draft text limit reached` when 1,000 fields were remembered (or the text was over 1,000 characters, or the field id over 400). Every caller (`explore-level.ts`, `author-view.ts`, `worksheet-view.ts`, …) calls it before handing the number to the model, so the typed value was silently dropped.

**Fix.** It never throws. A new field when 1,000 are remembered evicts the oldest remembered field (insertion order, which is creation order: re-typing an existing field does not reorder it, so the stored bytes change only when an eviction happens). Text over 1,000 characters or an id over 400 is not remembered; an older remembered text for that same field is dropped so it cannot be restored as current. The 1,000 fields × 1,000 characters cap is kept.

**Test** (`workspace-numeric-drafts.test.ts`, "keeps typing effective after 1,000 remembered fields …"): fill 1,000 fields, type a new one through a caller-shaped helper (remember, then model); the model gets the number, the oldest field is evicted, 1,000 remain; a 1,001-character text and a 401+-character scope do not throw and the cap holds.

Before:
```

AssertionError: expected [Function] to not throw an error but 'Error: Numeric draft text limit reach…' was thrown
 ❯ tests/workspace-numeric-drafts.test.ts:82:62
```
After: passes; the 7 existing tests in the file are unchanged and pass.
