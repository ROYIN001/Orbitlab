# R1.1 — Local learner workspace storage

Date: 2026-10-03. Plan: `Orbitlab-Development-Plan-TH.md`, R1.1 / contracts §4.2, decisions D01 and D04. Implementation branch: `codex/r1-profiles-foundations`. Integration, PR, merge, deployment and final candidate validation are tracked by the root progress report; this report does not assert they have happened.

## Delivered in this package

- Stable profile IDs, duplicate display names, create/rename/explicit selection/deletion, a separate selection per browser tab, and profile summaries/counts.
- A fixed owner and epoch for every document. Switching flushes owned editors, seals the old binding, and reloads the application. An old timer, assessment completion or pagehide save cannot resolve the next profile and write into it.
- All supported personal persisted work shares that binding: mission setup; saved rockets and satellites; lessons, examination attempts, imported/custom lessons and questions; experiment notebook; rocket/satellite/requirements drafts; both authoring drafts and their current kind; worksheet forms; uploaded recordings; personal language, mode, route, experience, guide, notation, HUD placement/readouts, city, sound and glow preferences.
- Literal unfinished numeric text has its own versioned record (`orbitlab.numeric-drafts.v1`), with design IDs and field IDs. Examples such as `1e-` and `0,08` are retained as text, separately from JSON's NaN/null representation. Rocket invalid counts/stretch and requirements invalid numbers restore as invalid fields instead of discarding the entire draft or silently substituting defaults.
- Learning reset, exam reset, combined reset and individual lesson reset use one atomic profile-record replacement. Full existing progress validation remains strict. Custom teaching content and unrelated work survive. The previous epoch is invalidated before further results can be stored.
- Reset handles valid progress recovery copies with the same scope. A damaged progress copy or pending old project-import rollback blocks reset rather than discard content or replay deleted history. Whole-profile deletion also deletes its owned recovery copies.
- Active/last-profile deletion leaves an explicit chooser. A failed media deletion keeps a durable deletion tombstone; the owner lock is still released, and startup retries the remaining operation.
- JSON backups of one or all learners include raw stored strings, IDs, names, source timestamps/revisions/epochs, persisted drafts and preferences. Imports default to fresh identities; targeted imports default to Keep Existing. The old `orbitlab.project` version 1 reader remains supported.
- JSON retains the existing 8 MB limit and explicitly states that uploaded media is omitted. A separate bounded binary audio archive provides preview, per-owner export and atomic media import, with Keep Existing default. It does not encode recordings into JSON/base64.
- Strict external import validation runs on demand. Invalid/newer primary records and external recovery journals/copies are retained byte-for-byte under owned `orbitlab.import.quarantine.v1`, and remain inert. Import preview reports how many values need this treatment. Unsupported content is preserved as recovery data, not represented as activated/restored content.
- The storage adapter also retains malformed JSON and unsupported-version bytes before a forgiving local loader first overwrites them. No account tokens, dataset caches, service workers or unrelated keys are enumerated for deletion.

## Architecture decision

Existing application persistence APIs are synchronous. For this release, each learner's raw values and metadata live in **one authoritative localStorage record**, so ordinary writes, resets and targeted JSON restoration are single-key atomic commits. A page holds an exclusive Web Lock for its profile while writing. Catalogue creation/deletion/publication uses a separate Web Lock; source inspection followed by localStorage writing is not presented as a cross-tab transaction.

A second tab for the same profile receives a labelled read-only binding. It may select/create another profile. If Web Locks or durable storage cannot initialize, the application receives an explicitly temporary, visit-only copy and performs no unlocked durable writes. Profile changes/resets/media imports are unavailable through the temporary UI. Temporary learning can continue, but closing the page loses those visit-only changes.

`src/workspace/storage.ts` is a lightweight adapter entrypoint. Bootstrap owns `src/workspace/session.ts`; metadata and locking live in `repository.ts`. Heavy legacy/strict external validators live in lazily imported `archive.ts`, so application startup does not statically depend on the lesson authoring/validation graph. `reset()` and external archive parsing now return promises; callers must await their committed result before reloading.

Migration and deletion routines now live in lazily imported `src/workspace/media-ownership.ts`. The shell/bootstrap has no static import or runtime re-export of that destructive module. Its callback remains awaited inside initialization/deletion, preserving the transaction, tombstone and pending-migration semantics. `media.ts` retains the shared database opening/readout helpers and lightweight key encoding; it does not re-export ownership mutations.

Custom recordings remain in IndexedDB `orbitlab-soundtracks`/`tracks`, now keyed by `(profileId, missionId)`. Their original legacy transfer is an idempotent single-database transaction. Profile JSON and media are **not** claimed to share a transaction. Deletion uses a catalogue tombstone and startup recovery around those two stores. Media migration collisions preserve both old and owned recordings and leave migration pending; they are not silently resolved by deleting either recording.

## Migration and rollback policy

The initial legacy owner receives all registered original raw strings, including recognized lesson recovery suffixes. Destination bytes are verified before the catalogue/migration marker is committed. Only unchanged allowlisted originals are removed after that commit. A quota failure before the marker leaves originals and the destination available for retry; no empty data is written over unknown versions.

If an older app changes original source bytes during an interrupted migration, the prior destination and the changed source become separate recovered/current owners rather than overwrite each other. Repeated incompatible interruptions remain blocked/temporary with their raw bytes retained. A cached pre-profile app can still create old unscoped keys; this release ignores those keys after migration and does not assign their new contents to another learner. Rolling back to an old application cannot read profile records; export a compatible project before intentionally moving to such a version.

Editor transition flushes retry only actual dirty/pending edits in the numeric cache, rocket/satellite drafts and requirements forms; mere construction, rendering, cache reads, backup and pagehide do not normalize untouched opaque/future primary bytes. Explore initialization computes without scheduling persistence, and actual input marks dirty before its deferred drawing work. A personal satellite edit put aside for a temporary lesson is still flushed as personal work; temporary lesson edits never overwrite that personal draft. Author/worksheet pending-state fixes are coordinated with the UI owner. Pending editor transitions are retried strictly. Quota failure leaves the current workspace open and binding valid. Timer/pagehide saves remain guarded, with a persistent storage-write notice/event; they are not proof that a failed write succeeded.

## Limits and remaining integration responsibility

- This is local data separation, not authenticated identity or an access-control boundary. Existing result checksums are not signatures or identity verification.
- A stored profile holds supported inputs, observations and drafts. It does not persist every live simulation frame or resume a running physical flight; switching warns and rebuilds a new session.
- Bounds are 40 profiles, 8 MB per JSON archive, 128 MB per binary media archive, 100 media tracks/header limit 100 KB, and 1,000 literal numeric draft fields with up to 1,000 characters each. Browser localStorage/IndexedDB quotas may be smaller and are handled as failures.
- Inert recovery values require a compatible future reader or deliberate repair/export; they are not silently copied back into active application keys. Ordinary profile deletion removes those owned values too.
- Stored raw bytes from earlier versions are preserved, but UI rendering of unsupported fields is not claimed to be implemented. Full flight persistence, online sync, sharing/login, R2–R7 and complete fleet physics are outside this package.
- Root must report exact final source/test/deployment status, retain a progress index mapping task IDs to this report, and complete real browser plus current-candidate CI checks before PR/merge.
