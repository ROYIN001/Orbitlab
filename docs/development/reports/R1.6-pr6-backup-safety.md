## M-PLATFORM-008 (P2): a backup near 8 MB could be a file that cannot be restored

**What failed.** `checkedExport()` in `repository.ts` measured the compact JSON (`JSON.stringify(archive)`) against `WORKSPACE_MAX_BYTES` (8,000,000) and then cloned the archive (one more stringify and parse). The menu (`profile-menu.ts` `download()`) then stringified a third time in indented form plus a newline and downloaded that. In the tests, indentation added 123 bytes for one learner and 206 bytes for two, so an archive whose compact form fitted could be downloaded over 8 MB. The app's own import then refuses it, first on `file.size > WORKSPACE_MAX_BYTES` in the menu and then on `PROJECT_MAX_BYTES` in `parseWorkspaceArchive`. Thai text makes this edge easier to reach than the character count suggests: each Thai character is 3 UTF-8 bytes in the file, so about 2.7 M characters of Thai work already make an export of about 8 MB.

**Fix** (S10 acceptance: stringify once in the format that is downloaded, check that text, download the same text; fall back to compact when only compact fits):
- `repository.ts`: the new `workspaceArchiveText(archive)` makes the indented text plus newline (the exact bytes main saved). It returns that text when it fits the import limit (the same `length` and UTF-8 byte test as before). Otherwise it returns the compact text when that fits, and otherwise throws `oversize`. `checkedExport()` is removed. `exportProfile()` and `exportAll()` return the archive object without a second stringify or clone, because `read()` already returns a private copy. Their doc comment says the limit applies to the saved text.
- `profile-menu.ts`: `download()` saves `workspaceArchiveText(archive)` in place of its own `JSON.stringify(archive, null, 2) + '\n'`. The file name and MIME type are unchanged.
- Normal size: the indented form is tried first and kept when it fits, so a normal backup is byte for byte the same as before. A test proves this against main's own output (below).
- Cost: a normal export now stringifies once and encodes once. Before, it did three stringifies, one parse and one encode.

## M-PLATFORM-009 (P3): visit-only delete would erase the saved profile's audio

**What failed.** In visit-only mode, `initializeEphemeral()` keeps the saved profile's real id in memory (for example `legacy-v1`). The `media` adapter is still the real IndexedDB store. `delete(id)` went through `withOwner` (the binding is writable), `withCatalog` (no lock when ephemeral) and `finishDelete()`, which called `media.delete(id)`. That erases the saved profile's uploaded audio while its durable record stays. The dialog disables Delete in visit-only mode, so this cannot be reached today. Before the fix, the test shows `media.delete` called with `legacy-v1`.

**Fix** (S10 acceptance: skip `media.delete` in visit-only mode, or throw `locked`): `delete()` now throws `WorkspaceError('locked')` first when the repository is ephemeral, before `prepareChange()`, the catalogue or media are touched. `exportMedia` and `importMedia` already refuse visit-only mode with the same code. The durable path is unchanged, and a guard test covers it.

## Notes for review

- `exportProfile()` and `exportAll()` no longer throw `oversize` themselves. The limit is now checked once, on the text that is saved (`workspaceArchiveText`), and the menu is the only code that saves an archive. No existing test relied on the old place of the check. The user sees the same `oversize` message at the same moment, before any download.
- The menu's import check (`WORKSPACE_MAX_BYTES`) and `parseWorkspaceArchive`'s check (`PROJECT_MAX_BYTES`) are both 8,000,000. The export now checks against `WORKSPACE_MAX_BYTES`. If the two constants ever differ, the export should check against the smaller one. That is not changed here.
- Not done here: `exportAll()` still reads each record twice (`list()` and then `read()`). That read cost belongs to M-PLATFORM-005 (R1.6 PR4).
