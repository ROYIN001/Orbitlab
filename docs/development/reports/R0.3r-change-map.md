## What was added

- `scripts/verification/change-map.json` holds the map. It turns the prose table in VERIFICATION.md into 33 rules.
  - Each rule matches paths by glob (`paths`, with an optional `exclude`).
  - Each rule names checks with the names the verification plans already use: the commands `typecheck`, `build`, `budget` and `node-verification`, plus the suites `unit`, `browser`, `heavy` and `sixdof-fleet`. Suite contents come from `discoverFiles` in `lib.mjs` and from `tests/browser/journeys/*.mjs`.
  - Named sets (`@flight-journeys`, `@layout-journeys`, …) keep journey lists in one place.
  - Two rules are `additive`. `always-repo-hygiene` applies to every path. `app-build` gives every app source `typecheck`, `build` and `budget`. Neither one counts as a known impact.
  - `fallback: {all: true}` means a path with no domain rule selects the full set: every command, all 298 unit files, all 33 journeys, all 33 heavy files and all 6 fleet files. This follows S18: "if the impact is unknown, run the full set."
  - `toolchain-and-public` (lockfile, configs, `budgets.json`, `public/**`) also selects the full set.
- `scripts/verification/select-checks.mjs` takes `<base>..<head>` (diffed from the merge base, renames split into both paths), `--files …` or `--stdin`. It validates the map against the current inventory, then prints the selection and the commands to run. `--json` prints the selection as data.
- `tests/verification/change-map.test.mjs` runs under `node --test`. Its trial data is in `tests/verification/change-map-trials.json`.
- VERIFICATION.md has a new section, "Machine-readable map (R0.3r)".

## The trial

How a trial runs:
- The changed files come from GitHub REST `pulls/{n}/files` or `git show --name-only`.
- `tests/**` is removed from the change, so a test cannot select itself.
- Each expected check must be selected twice:
  1. by the whole change;
  2. by the culprit path alone, through a domain rule. This selection must not be the full set. Many of these PRs also touch an unmapped path or the lockfile, which selects everything, so without this second condition a check would be selected trivially.

## Limits

- The rules are by path, not by import graph. A shared module that a rule names too narrowly would still be caught by the complete gates, which keep running.
- Selecting by import graph (for example `vitest related`) could narrow the unit selection later. It is not part of this package.
- Wiring the selection into CI is a later package (R7.3). Its timing benefit is not measured here: KPI-28 still needs real runs.
