4. **สถานะ** (แถวที่เจ้าของยืนยันเท่านั้นจึงเขียนว่า "ตัดสินแล้ว"):

| สถานะ | ความหมาย | ใครตั้ง |
|---|---|---|
| ตัดสินแล้ว (decided) | เจ้าของยืนยัน มีวันที่และคำพูดหรือลิงก์ | H; I บันทึก |

| เบี่ยง (deviated) | งานที่ทำจริงต่างจากคำตัดสิน | I จากผลตรวจ แล้วถามเจ้าของในชุดถัดไป |

| เปิด (open) | ถามแล้วแต่ยังไม่ได้คำตอบ | I เมื่อส่งชุดคำถาม |
| เลื่อน (deferred) | เจ้าของเลือกตัดสินทีหลัง หรือรอหลักฐาน (ระบุเงื่อนไขเริ่ม) | H |
| เสนอ (proposed) | agent ร่างไว้ ยังไม่ได้ถาม | agent ใดก็ได้ |

5. **กติกา:**
   - เมื่อไม่มีคำตอบ ใช้กติกา PLAN:§11.2 ต่อไป: คำถามที่ยังไม่ตอบไม่ถือเป็นการอนุมัติ งานเอกสารทำต่อได้ แต่ implementation ที่ขึ้นกับคำตอบเป็น blocked จนกว่าจะได้คำตอบหรือเจ้าของมอบให้ใช้สมมติฐานอย่างชัดแจ้ง สมมติฐานที่เจ้าของมอบให้ใช้กลายเป็นแถว "ใช้แล้ว รอยืนยัน" ที่มี needed-by ส่วน agent มอบสมมติฐานให้ตัวเองไม่ได้ (บทเรียน: รายงาน R2 เขียนว่า "ถ้าผู้ใช้ไม่เห็นด้วยกับข้อใด ให้ปรับก่อน merge" แต่ #74 merge ก่อนเจ้าของตอบ D08)
   - ถามเป็นชุดตามคลื่น (§08.5) ในรูป "ทางเลือก + ข้อเสนอ" (process lesson A4) โดย I บันทึกวันที่ส่งชุดคำถามและวันที่ได้คำตอบ ความหน่วงเทียบ needed-by คือ KPI-35 (นิยามใน S04)
   - การเปลี่ยนคำตัดสินเดิมทำได้โดยเพิ่มแถวใหม่ที่อ้างแถวเดิม แถวเดิมคงข้อความไว้และเติมหมายเหตุ "แทนโดย D-n" ไม่มีการแก้ข้อความย้อนหลัง
   - agent ที่พบว่างานต้องใช้การตัดสินใจที่ยังไม่มีในทะเบียน ต้องหยุดขั้นนั้น แล้วเขียนแถว "เสนอ" พร้อมทางเลือกและข้อเสนอ ห้ามขยายขอบเขตเอง
