### 09.1 นิยามและกฎของแทร็ก EQ

**สิ่งที่ "เหมือนเดิม" ต้องคงไว้** ใช้ตารางราย domain ใน S02 §02.3 (OR-1) ตรงตัว ได้แก่ ฟิสิกส์ bit-identical บน engine เดียวกัน, digest ของเครื่องมือ Orbit, ไบต์ของข้อมูลที่เก็บและไฟล์ส่งออก, พิกเซล DOM และข้อความ, และไบต์ใน cache ที่ตรง revision ส่วนนี้เพิ่มเฉพาะขอบเขตของสิ่งที่**เปลี่ยนได้**ใน PR ชนิด EQ:

| เปลี่ยนได้ (คือเป้าของ EQ) | เปลี่ยนไม่ได้ |
|---|---|
| เวลา (interactive, frame gap, long task), จังหวะที่งานเกิด (ย้ายไป idle หรือ worker), จำนวนงาน (program, draw, deriv call, การอ่าน storage, การเรียก SGP4), ไบต์ที่**ส่งผ่านเครือข่าย**, ขนาด chunk, เวลาโหลดของโมดูล | ทุกค่าที่ oracle ใน S07 §07.5 ครอบ, ลำดับ cascade และ scene graph, ข้อความที่ผู้ใช้เห็นในแต่ละช่วงเวลาที่วัดได้ด้วย DOM snapshot, ความครบของ precache และการใช้งานออฟไลน์, ค่าสูงสุดของหน่วยความจำต้องไม่เกินค่าสูงสุดเดิม (เว้นแต่วัดแล้วและอยู่ในงบ KPI-32) |

**กฎ (ใช้กับทุก PR ชนิด identical-output ไม่ว่าแพ็กเกจจะอยู่ที่ใด):**

1. **oracle ต้องบันทึกบนฐานก่อนแก้:** envelope ระบุ `oracle: [EO-…]` จาก S07 §07.5 อย่างน้อยหนึ่งตัวต่อ domain ที่ PR แตะ oracle แบบ R (fingerprint, digest) บันทึกครั้งเดียวบน CO-6 base (SHA ของ Day 0) ส่วนแบบ D รันบน merge-base ของแต่ละ PR ถ้า kit ของ M-PLAN-018 ยังไม่ merge ให้ใช้ oracle เฉพาะ PR ที่เป็น commit แรกของ PR เขียวบน merge-base และพิสูจน์ด้วย sabotage แล้ว (แบบเดียวกับ CO-4; S07 §07.5) **ไม่มีใครบันทึก oracle ใหม่ใน PR ของ EQ**
2. **หนึ่งชนิดต่อ PR:** identical-output ไม่ปนกับ bug-fix, quality-improving, feature หรือ realism-changing ถ้ารายการหนึ่งมีทั้งส่วนที่เหมือนเดิมและส่วนที่เปลี่ยนผล (เช่น M-BUILD-027, M-LAUNCH-086, M-PHYSICS-015) ให้แยกเป็น PR ติดกันในเลนเดียวกันตาม fold (S18 §18.4)
3. **อ้างความเร็วได้ด้วย `--compare` เท่านั้น:** ฝั่งละอย่างน้อย 3 รอบ ช่วง min–max ต้องไม่ทับกัน และต้องเป็น KPI ที่ไม่ขึ้นกับฮาร์ดแวร์ (ไบต์, program, context, draw, การอ่าน storage, deriv call) ค่าเวลาเป็น trend และตัวเลขที่จะเผยแพร่ต้องมีอย่างน้อย 5 รอบ (S04 §04.1 ข้อ 2–4) ถ้ายังไม่มีหลักฐานให้เขียนว่า "ต้องวัด"
4. **KPI อื่นห้ามแย่ลง:** ถ้า `--compare` ยืนยันว่า KPI ใดแย่ลง (เช่น first open ช้าลง, startup program เพิ่ม) ห้าม merge (S04 §04.1 ข้อ 4)
5. **กฎหยุด:** ถ้า oracle ขยับ PR นั้นไม่ใช่ EQ ให้ทำตาม S07 §07.5 คือรันฐานซ้ำ ถ้าฐานไม่เสถียรให้แก้ oracle ใน PR แยก ถ้าฐานเสถียรให้ปฏิเสธ หรือวางแผนใหม่เป็นชนิดอื่นโดยเจ้าของอนุมัติ การ re-record ที่ไม่ได้ตั้งใจนับใน KPI-21
6. **ลำดับ D-63:** ในเลนเดียวกัน EQ มาก่อน ยกเว้นบั๊ก P0/P1 ที่ทำข้อมูลหายหรือแสดงผลเท็จในไฟล์เดียวกัน ซึ่งต้องไปก่อน ตัวอย่าง: CO-4 ขั้น 1 ก่อน EQ-3, PR bug-fix ของการ sample GlowGovernor ก่อน EQ-3 (§09.5), FX-7 ขั้น 0 ก่อน EQ-1, FX-1 ก่อน EQ-13 และ FX-2 ก่อน EQ-14 ฝั่งบทเรียน
7. **เริ่มได้เมื่อมี oracle ที่ PR ระบุ ไม่ต้องรอ R0.4 ทั้งชุด (S07 §07.4):** PR ของ EQ แต่ละตัวต้องมี**เฉพาะ** oracle ในแคตตาล็อก (S07 §07.5) ที่ envelope ระบุด้วยรหัส `EO-…` แต่ละตัวบันทึกบนฐานแล้วและพิสูจน์ด้วย sabotage แล้ว (จาก kit ของ M-PLAN-018 หรือเป็น oracle เฉพาะ PR) และต้องมี M-PLATFORM-041 (`--compare`) **เฉพาะเมื่อ PR อ้างว่า KPI เปลี่ยน** ถ้าอ้าง KPI ใน scenario ที่ยังไม่มี ต้องรอ scenario นั้นด้วย เช่น Build (M-BUILD-025) และ server แบบ Pages (R0.4 ขั้น 8a ซึ่งมาพร้อมขั้น 1) ผลต่อคลื่น: EQ-1 เริ่มได้ใน K1 (EO-PWA-1 + ขั้น 1), EQ-4 และ EQ-9 เริ่มได้ใน K2 (EQ-9 เป็นงานต้น K2 ของเลน P) ส่วน EQ-10 และ EQ-11 ย้ายมา K2 หลังตรวจ `depends_on` ใน ledger แล้วว่า R0.4 ที่ต้องมีคือ M-PHYSICS-002/003 เท่านั้น (M-PHYSICS-012: 001, 003; 013 และ 014: 001, 002; 015: 001; M-PHYSICS-011: 002; โดย 001 คือ CO-6 ใน K0 และ EQ-9 มาก่อนในเลน P เดียวกัน)
8. **E ก่อน F:** EQ บนไฟล์ใดต้องมาก่อนงาน realism บนไฟล์นั้น (EQ-9/10/11 ก่อน R4.2/R4.3/R4.5/R5/R8) และเมื่อมี re-baseline ฟิสิกส์ ห้ามมี PR EQ-ฟิสิกส์เปิดพร้อมกัน (S05 §05.7)
9. **งบขนาด:** PR ของ EQ ที่ทำให้ chunk เล็กลง ห้ามแก้ `budgets.json` เอง T จะลดเพดานใน PR ratchet ถัดไป (S18 §18.3) EQ-1, EQ-6, EQ-7 และ EQ-8 เป็น offset ที่ระบุชื่อได้ตาม D-38 ต้องเขียนให้ชัดว่า EQ-1 และ EQ-6 ลดไบต์ที่ส่ง ไม่ได้ลดขนาด precache
10. **หลักฐาน:** ตามขั้นตอน S18 §18.9 และ DoD ของ EQ (S18 §18.12) envelope ระบุ `change_kind: identical-output`, `or_ids: [OR-1, OR-2]`, `perf_evidence`, `kpi_targets` และ `base_sha_verified_on` รายงานอยู่ที่ `docs/development/reports/EQ-<n>-<slug>.md` และต้องระบุเทสต์ที่รันจริง

### 09.3 กล่อง guard rail (อ่านก่อนเริ่มทุกแพ็กเกจ)

> **กฎหลักอยู่ที่ S02:** §02.10 (RA:(d) 1–8 และ "Exclusions to keep") และ §02.13 ข้อที่เกี่ยวกับ EQ โดยตรงคือ 3–10, 12, 14, 17, 18, 24, 27, 29 และ 30–42 ถ้าแพ็กเกจใดพบว่าต้องทำสิ่งในรายการนั้น ให้หยุดและเสนอทางที่รักษาคุณภาพผ่าน S19 App C
> **ข้อเตือนเฉพาะ EQ** (ไม่ได้เพิ่มกฎใหม่ แค่ย้ำให้เห็นในที่ที่ใช้):
> - **step size และนาฬิกาควบคุม 0.01 s ห้ามโตขึ้น** รวม `suggestedDt`, `TRANSIENT_DT`, เพดาน 3600 s และพื้น 0.5 s ของ Cowell และ tolerance 1e-10 ด้วย memo หรือ fast path ห้ามแตะสิ่งเหล่านี้
> - **cache ของ MSIS และ memo ทุกตัวใช้ key เป็นค่าของ input ตรงตัว** (`Object.is` บน jd และบนส่วนประกอบของสถานะ) ห้าม key ด้วย tolerance ห้าม key ด้วย identity ของ object ที่ถูกเขียนในที่เดิม (เช่น `state.r`/`state.v` ที่ `applyFrameToState` เขียนทับ, `scene.origin` หลัง M-LAUNCH-024) ห้ามจำค่าข้ามการเรียกเมื่อ input ภายนอก (EOP, TLE) เปลี่ยนได้ และค่าที่ memo คืนต้องผ่าน audit ผู้เรียกทุกตัวว่าไม่มีใครแก้ไข พร้อมเทสต์ (หรือคืนสำเนา) ไม่ใช้ `Object.freeze`
> - **การค้น pass ยังต้องเจอครบ 249 เหตุการณ์ของ Skyfield** (EO-ORB-1) ห้ามลดความละเอียดของ golden-section 0.1 s หรือการสุ่ม eclipse
> - **ลำดับการบวกและรูปนิพจน์เดิมเป็นส่วนหนึ่งของผล:** reduce จาก 0 จากซ้ายไปขวาโดยคงพจน์ที่สัมประสิทธิ์เป็นศูนย์, `a + b*s`, `(dt/6)*(((k1+2k2)+2k3)+k4)` และ signed zero ห้าม "ทำให้ง่าย"; ห้ามใช้ float32; คง frame ของ vector ดวงอาทิตย์และดวงจันทร์
> - **ข้ามได้เฉพาะงานที่พิสูจน์ว่าเป็น pure function ของ input ที่ไม่เปลี่ยน** ห้ามข้ามโดยดู visibility ตอน update (จะได้เฟรมเก่าหนึ่งเฟรม) และห้าม early return ที่ข้าม integrator, timer, เสียง หรือ camera damping
> - **ย้ายงานไป worker หรือ idle ต้องได้ตัวเลขเดิมทุกบิต** และต้องยกเลิกได้เหมือนเดิม ห้าม fallback ไป main thread แบบเหมารวม (ข้อ 14) แต่งานที่*ย้าย*โค้ด synchronous บน main thread ของวันนี้เข้า worker (M-ORBIT-006, M-PHYSICS-017 เมื่อเลือก worker, M-LAUNCH-084, M-BUILD-014) ต้องคงเส้นทาง synchronous เดิมไว้เป็น fallback ราย job เมื่อ constructor ของ `Worker` ล้มเหลว พร้อมข้อความแจ้งผู้ใช้และเทสต์ (ข้อ 14 เดียวกัน)
> - **lazy load และการสร้างเมื่อใช้ต้องไม่ทำให้การเปิดครั้งแรกช้าลง** (วัด 5 รอบ) และเฟรมแรกต้องเหมือนเดิม ไม่มีเฟรมว่าง ไม่มีภาษาอังกฤษโผล่ให้ผู้ใช้ TH/RU และ precache ยังครบสำหรับออฟไลน์ (ข้อ 18)
> - **cache ชั้นนิ่ง (วาดจาก offscreen bitmap) ใช้ได้เฉพาะเมื่อ oracle `getImageData` เท่ากันตรงตัวที่ DPR 1, 2 และ 3 รวมความกว้างเลขคี่และ offset ของแผนที่ที่ไม่ลงพิกเซลเต็ม ถ้าไม่เท่าให้ตัดส่วนนั้นออก** (ใช้ถ้อยคำเดียวกันใน EQ-4 และ EQ-7)
