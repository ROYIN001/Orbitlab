### 00.2 ข้อกำหนดสำหรับ AI ที่รับช่วง

> **อ่านก่อนเริ่มทุกครั้ง**
> 1. **ลำดับการอ่าน:** S00 → S05 (คลื่น ประตู และ Day 0) → S18 (เลน write set และ protocol) → ส่วนที่เป็นบ้านของแพ็กเกจ → แถวของรายการใน S19 App A → `docs/development/PROGRESS.md` บน main ปัจจุบัน
> 2. **ทำเฉพาะแพ็กเกจหรือขั้นที่เจ้าของอนุญาต** ตามคำสั่งตรงตัวและวันที่ใน envelope (S18 §18.11) ห้ามขยายขอบเขต และห้ามอนุมานว่าได้รับอนุญาตแพ็กเกจถัดไป (D-65) คำสั่งเดิมใน PROGRESS ("continue to phase 3 if R2 merged cleanly" และแถว R3.5 "Planned (authorized)" บน `7ddab75`; "ทำต่อเลยครับ" บน `7662ead`) ไม่ใช่คำอนุญาตแพ็กเกจของ v2.0 **เลน R3 ปิดแล้ว:** R3 ครบตามคำของเจ้าของ 2026-10-04 คำสั่งเดิม "ทำต่อเลยครับ" ไม่ครอบ R4 หรือแพ็กเกจใดของ v2.0 (แถว R4–R7 ของ PROGRESS บน `5f9aa2e` เขียนว่า "No implementation claimed or inferred authorization"; D-65) งาน R3+ ต่อยอดก็ต้องได้รับอนุญาตรายคลื่นหรือรายแพ็กเกจเช่นกัน
> 3. **ตรวจสถานะรายการซ้ำบน SHA ของ main ปัจจุบัน** ก่อนเริ่ม และบันทึกใน `base_sha_verified_on` ถ้าแผนกับโค้ดหรือ GitHub ไม่ตรงกัน ให้เชื่อโค้ดและ GitHub (§00.8)
> 4. **หนึ่ง PR มีการเปลี่ยนชนิดเดียว** (§00.6.5) งาน identical-output ไม่รวมกับชนิดอื่นเด็ดขาด
> 5. **แก้แถวของแพ็กเกจใน PROGRESS ภายใน PR ที่ merge** (KPI-31)
> 6. **เขียนรายงาน** `docs/development/reports/<package>.md` ที่ระบุเทสต์ที่รันจริง (ไม่ใช่ที่ควรรัน) ผล และข้อจำกัด
> 7. เจอการตัดสินใจที่ยังไม่มีในทะเบียน: หยุดขั้นนั้นและเขียนแถว "เสนอ" ใน S08 ห้ามตัดสินเอง ถ้าไม่มีคำตอบ งานรอ

**ความสำคัญ:** P0 = บล็อกการเผยแพร่หรือทำงานของผู้เรียนหายอยู่ตอนนี้; P1 = กระทบผู้ใช้หรือครูมาก หรือบล็อกประตู; P2 = สำคัญ; P3 = มีประโยชน์ ทำเมื่อเหมาะ
