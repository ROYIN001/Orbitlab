### 02.1 เป้าหมายสูงสุด

เป้าหมายสูงสุดคือรากฐานที่ฟิสิกส์ ข้อมูลอ้างอิง และสถานะการจำลองสอดคล้องกัน เพื่อให้การสร้างยาน การปล่อย การโคจร การเชื่อมต่อ ดวงจันทร์ และโหมดนักบินอวกาศใช้ระบบเดียวกันได้อย่างน่าเชื่อถือ สำหรับนักเรียนไทย นักเรียนนายเรืออากาศและกำลังพล ครู และผู้เรียนทั่วไป (RM:P1) บนโทรศัพท์ของตัวเอง แบบออฟไลน์ และบนเครือข่ายปิดของหน่วยงาน ทุกงานต้องเพิ่มทั้งประสิทธิภาพและความสมจริงไปพร้อมกัน (OR-3) โดยไม่ลดคุณภาพด้านใด (OR-2) งานของผู้เรียนต้องไม่หายแบบเงียบ และไม่มีผลที่ไม่จริงแสดงเป็นผลสมบูรณ์ ความสวยงามของภาพต้องสะท้อนสถานะจริงของการจำลอง ไม่ใช้ภาพเคลื่อนไหวจัดฉากแทนกลไกที่ยังไม่มี (ข้อความเดิมของ v1.2)

ย่อหน้าอื่นของ PLAN:§1 ยังมีผล: (ก) ผลชุดทดสอบ การเทียบข้อมูลการบินจริง และการประเมินความเข้าใจของผู้ใช้เป็นหลักฐานคนละชนิด รายงานแยก (S18 §18.8); (ข) "ถูกต้องสมบูรณ์" ต้องแปลงเป็นขอบเขตที่ตรวจได้ — กฎที่รักษา ปรากฏการณ์ที่รองรับ ช่วงสภาวะที่ตรวจ แหล่งข้อมูล ความไม่แน่นอน และกรณีที่ยังไม่ผ่าน; ไม่เปลี่ยน tolerance หรือข้อมูลอ้างอิงภายหลังเพื่อให้ผ่าน; (ค) การวางแผนรอบนี้ไม่ได้เปลี่ยนแอป รันเพียง perf baseline แบบอ่านอย่างเดียว (PB:) และอ่าน GitHub API

### 02.3 ข้อกำหนดของเจ้าของ OR-1…OR-6

ถอดความคำสั่งเจ้าของ (4 ต.ค. 2026) อย่างซื่อตรง ทุก task envelope ต้องมี `or_ids` (S18 §18.11) และ PR checklist (S18 §18.10) ต้องแนบหลักฐานตามหัวข้อ "พิสูจน์" สิ่งที่ยังไม่วัดเขียนว่า "ต้องวัด" ห้ามคาดเป็นตัวเลข

#### OR-1 — ทำงานที่ผลลัพธ์เหมือนเดิมทุกประการก่อน
- **คำของเจ้าของ:** "ทำการเปลี่ยนแปลงที่ผลลัพธ์ยังเหมือนเดิมทุกประการก่อน คือเพียงหยุดงานที่ซ้ำซ้อนหรือสูญเปล่า"
- **ความหมายเชิงปฏิบัติ:** งานแรกของแต่ละเลนคือ PR ชนิด identical-output ที่ตัดงานซึ่ง*วัดแล้ว*ว่าซ้ำ (S03 §03.5, S09 §09.2) สิ่งที่ผู้ใช้เห็นและไฟล์ที่ได้ไม่เปลี่ยนแม้แต่บิต; เวลา จังหวะเฟรม ไบต์ที่ดาวน์โหลด และปริมาณงานเปลี่ยนได้ — นั่นคือเป้า
- **นิยาม "เหมือนเดิม" ราย domain** (oracle อยู่ใน S07 §07.5):

| domain | "เหมือนเดิม" หมายถึง |
|---|---|
| ฟิสิกส์และ worker | bit-identical บน JS engine เดียวกัน (Node 22.23.3 / V8 เดียวกัน; RA:(d)8); ข้าม engine ใช้ tolerance ของ T02 (1.4e-12 s, 1.4e-11 m/s) ซึ่งห้ามผ่อน |
| เครื่องมือ Orbit | digest เท่าเดิม รวมเหตุการณ์ pass ทั้ง 249 ที่เทียบ Skyfield (M-PLAN-010) |
| ข้อมูลที่เก็บและไฟล์ส่งออก | byte-identical: record ใน storage, archive, CSV, DOCX, HTML, JSON, notebook |
| ภาพ, DOM, ข้อความ | พิกเซลเท่าเดิม (readPixels hash / screenshot diff = 0), DOM เท่าเดิม, ข้อความที่ resolve ต่อ key ต่อภาษาเท่าเดิม |
| PWA และบันเดิล | ไบต์ใน cache ตรงกับ revision SHA-256 ใน manifest; ผ่านการตรวจ sourcemap |

- **กฎลำดับ D-63:** ในแต่ละเลน identical-output มาก่อน *ยกเว้น* บั๊ก P0/P1 ที่ทำข้อมูลหายหรือแสดงผลเท็จในไฟล์เดียวกัน ซึ่งทำก่อน เพราะความปลอดภัยข้อมูลคือคุณภาพตาม OR-2 (ตัวอย่างใน §02.4)
- **ห้าม:** ผสม identical-output กับชนิดอื่นใน PR เดียว; บันทึก oracle ใหม่ภายใน PR ชนิด EQ (ไม่มีใครมีสิทธิ์); ใช้ tolerance แทน hash เพื่อพิสูจน์ว่าเหมือน; อ้างว่าเร็วขึ้นโดยไม่มี `--compare` ถ้า oracle ขยับ PR นั้นไม่ใช่ EQ — ปฏิเสธ หรือวางแผนใหม่เป็นชนิดอื่นโดยเจ้าของอนุมัติ (stop rule, S07 §07.5)
- **พิสูจน์:** envelope `change_kind: identical-output`, `or_ids: [OR-1, OR-2]`, `oracle:` (id จาก S07 บันทึกบน base SHA ก่อนแก้), `perf_evidence:` `measure.mjs --compare` ≥ 3 รอบ ช่วงไม่ทับกัน บน KPI ที่ไม่ขึ้นกับฮาร์ดแวร์ (S04); ขั้นตอน S18 §18.9

#### OR-2 — ห้ามลดประสิทธิภาพหรือคุณภาพ
- **คำของเจ้าของ:** "ห้ามทำการเปลี่ยนแปลงใดที่ลดประสิทธิภาพหรือคุณภาพ ทั้งคุณภาพภาพ ความลื่นไหล ความสมจริงทางฟิสิกส์ ความปลอดภัยข้อมูล ความเข้ากันได้ และประสบการณ์ผู้ใช้"
