### 04.2 ตาราง KPI-01…KPI-35

**ชนิด gate**
- **hard:** ไม่ผ่านแล้ว PR หรือประตูไม่ผ่าน
- **ratchet:** hard ที่ใช้ค่าดีที่สุดที่บันทึกไว้เป็นเกณฑ์ ขยับได้ทางเดียว แก้โดย T เหมือน `budgets.json`
- **trend:** รายงานด้วย `--compare` ไม่เป็นประตูเอง แต่การถดถอยที่ยืนยันแล้วห้าม merge (04.1 ข้อ 4)
- **human:** มาจากแบบฟอร์มหรือรายงานอุปกรณ์ เจ้าของตัดสินที่ประตูความสามารถ
- **execution:** ตัวชี้กระบวนการ รายงานที่ GK เพื่อปรับ WIP และแผน (S05 §05.11) ไม่บล็อก PR

**ตรวจเมื่อ:** PR = ทุก PR ที่แตะ KPI นั้น; GK = ประตูท้ายคลื่น (S05); ชื่อประตู = ประตูความสามารถ (G2, G3, G4-S, G4, G5, G6, G8) ก่อนเครื่องมือของ R0.4 ลง repo ค่าระดับ PR ที่วัดด้วย `measure.mjs` ยังบังคับใน CI ไม่ได้
