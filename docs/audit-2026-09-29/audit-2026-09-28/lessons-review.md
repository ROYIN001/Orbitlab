### L2 — P2: “Show the answers” creates a permanent learning dead end

**Confirmed behavior in source and executed tests; pedagogical severity is a recommendation.** The old implicit answer disclosure after a wrong submission is fixed. However, a displayed expected value is now stored across all attempts (`src/lessons/progress.ts:51–55,141–149`). `wasRevealed()` applies the answer tolerance, and `regradeAnswers()`/`gradeCaseLesson()` fail any matching expected value regardless of the new response (`src/lessons/grader.ts:31–35,224–236`; `src/lessons/case-grader.ts:23–37`). The UI disables the corresponding input (`lesson-mode.ts:611,767,780`); Restart clears answers but keeps revelation history (`:316–334`). Executed `tests/lessons-ui-core.test.ts` deliberately verifies that the same flight can never pass again; `tests/case-lessons.test.ts:128–138` does the same for cases.

For 1.1 the fixed orbit repeatedly produces the same period/speed within tolerance. For all three cases the final “why” choice index is fixed, so revealing that answer blocks the whole lesson on subsequent visits even when live data change. There is no alternate assessment/recovery flow in the lesson code. The button title warns about lifetime consequences (`src/i18n/en.ts:3168`), but an initial untouched form only visibly says “Show the answers”; tooltip-only guidance is particularly weak on touch devices. Failure also withholds the flight debrief and next-lesson button (`lesson-mode.ts:637–655`).

**Recommendation:** record “completed with solution/help” for this attempt, then offer a new parameter/example or a clearly labelled practice retry. Keep assisted practice distinct from independent demonstration without permanently punishing a request for explanation. The new behavior is intentional in tests, so this is a request to revise the product policy, not an assertion that implementation accidentally contradicts its tooltip.

### L3 — P2: lesson 1.5 presents a simplified launch corridor as a real-world prohibition

**Confirmed content issue, independently checked against a primary source.** `src/lessons/builtin/track1.ts:136–138` says Falcon 9 from Cape would have to fly north for a polar orbit and the range does not license it. The fresh test at `tests/lessons.test.ts:154–160` verifies that the simulator rejects Cape and accepts Vandenberg. But the official [Space Launch Delta 45 account](https://www.patrick.spaceforce.mil/News/Article-Display/Article/2889083/sld-45-to-support-multiple-southerly-trajectory-launches-in-new-year-urges-publ/) says SAOCOM-1B restored Florida's polar-launch capability in August 2020 and reports two polar-trajectory missions from Cape in 2021. The lesson should say **“within this simulator's simplified corridor”** and explain the omitted southern dogleg, or add that capability. Keep the useful exercise about site, inclination and range constraints.
