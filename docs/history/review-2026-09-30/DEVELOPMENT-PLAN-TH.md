> "ยกระดับเว็บนี้ไปอีกขั้น" สำหรับ Orbitlab ไม่ได้หมายถึงฟิสิกส์ที่มากขึ้นหรือเนื้อหาที่มากขึ้น — แอปมีความลึกระดับห้องปฏิบัติการมหาวิทยาลัยอยู่แล้ว (ฟิสิกส์ที่ validate, 24 บทเรียนให้เกรด, ดาวเทียมจริง, ผู้สร้างจรวด) แต่อยู่หลัง *ทางเข้าของเดโม* ขั้นต่อไปคือทำให้มันเป็น **เครื่องมือการสอนที่สถาบันถือได้**: นักเรียนไทยบนโทรศัพท์ของตนเองออฟไลน์ถึงผลแรกในสามนาทีและอ่านได้ว่าทำไมเที่ยวบินจบแบบนั้น; นักเรียนนายเรืออากาศทำ lab ระบบควบคุมใน Engineer พร้อมคู่มือรัสเซีย; ครูแจกไฟล์และตรวจไฟล์ที่นักเรียนส่งโดยไม่มีเซิร์ฟเวอร์; โรงเรียนหรือหน่วยติดตั้งจาก zip บนเครือข่ายปิดใน 30 นาที; ทุกตัวเลขมีแหล่งและเทสต์ที่ยึดมันไว้ — โดยฟิสิกส์ใต้ทั้งหมดไม่เปลี่ยนแม้บิตเดียว

## 1. วิสัยทัศน์ — "จากเดโมที่มีความลึกของห้องแล็บ สู่เครื่องมือการสอนที่สถาบันถือได้"

ภายใน 12 เดือน Orbitlab ควรเป็น:

1. **สำหรับนักเรียนไทยบนโทรศัพท์ (ออฟไลน์)** — เปิดจากลิงก์ที่ครูส่งใน LINE, เห็นชื่อทุกปุ่ม, ตัวอักษรไทยไม่ถูกตัด, แตะหนึ่งครั้งถึงสถานะ "กำลังทำ", ทำนายก่อนบิน, เห็นการ์ดที่บอกว่า "วงโคจรไม่ถึงเพราะเชื้อเพลิงหมดที่ T+512 ก่อน circularise — ลอง −500 kg?" พร้อมปุ่มดูขณะนั้น, ส่งผลลัพธ์กลับเป็นไฟล์ที่ครูตรวจได้
2. **สำหรับนักเรียนนายเรืออากาศใน Engineer** — lab ระบบควบคุมอากาศยาน 4–7 งานในสัญกรณ์ ГОСТ (Bode ที่ max-Q, margins, step/doublet, notch/bending, INS/Kalman, PEG/IGM, Monte Carlo) พร้อมรายงานส่งออก HTML และ Auto Tune ที่ยกเลิกได้ ไม่ล็อกเธรด
3. **สำหรับครู** — คู่มือไทย 10 หน้า, แผนที่หลักสูตร สสวท. ที่เทสต์ยึดกับแคตตาล็อก, แพ็กบทเรียนเป็นไฟล์, worksheets DOCX, มุมมองรีวิวที่ตรวจ checksum และ *บินซ้ำ* ภารกิจของนักเรียนภายใน tolerance, โหมดนำเสนอบนโปรเจกเตอร์
4. **สำหรับสถาบัน** — release ที่มีหมายเลข (zip + SHA256SUMS + build-info + LICENSE + NOTICE), คู่มือติดตั้งเครือข่ายปิด TH/EN, ชุดรีเฟรชข้อมูลจาก USB, mirror, ผู้ดูแลคนที่สอง, รายงาน validation ที่อ้างอิงได้ซึ่ง *สร้างจากเทสต์*
5. **สำหรับตัวฟิสิกส์** — 18/21 ยานเทียบกับ timeline สาธารณะ, rating ที่ *บิน* ไม่ใช่นับ, launcher ที่ size แล้วบินถึงจริง, J2 อันดับสองใน playground, ดาวเทียมเป็นวัตถุกายภาพชิ้นแรก (eclipse/พลังงาน — ฟิสิกส์เบื้องหลัง NAPA-1/2), DOP และเศษซาก ASAT เป็นแนวคิดจากแหล่งสาธารณะ — ทั้งหมดบน goldens ที่ไม่เปลี่ยน
6. **สำหรับเจ้าของ** — CI ตอบใน 10 นาที, ทุกกฎที่แคร์เป็นเทสต์สีแดงไม่ใช่ความจำ, PR จาก AI session มี template และเทสต์สุขอนามัยกัน, และเวลาต่อเดือนที่ใช้ *น้อยกว่า* วันนี้

## 2. หลักการที่ทุกรายการในแผนนี้ต้องผ่าน

1. **ผู้ใช้จริงก่อนออกแบบใหม่** — S9 (ทดสอบผู้ใช้ 5–6 คน) เป็นประตูของ S11/S12/S16 ตาม PLAN §7; ก่อนประตูเปิด ทำได้เฉพาะ *metadata* และการแก้ข้อบกพร่องที่ *รู้แล้ว* (ชื่อโหมดที่ซ่อน, ตัวอักษรไทย, เวลาบนการ์ดบทเรียน, ค่าเทียบขอบ, ปุ่มกระโดด) ไม่ใช่การจัดหน้าใหม่
2. **ฟิสิกส์ validate ก่อน build; การสอนและเกมอยู่ *บน* ฟิสิกส์ ไม่เข้า `src/physics`** — challenges/campaign/คะแนน/วินิจฉัย import จากฟิสิกส์แค่ types (เทสต์บังคับ); tolerance กำหนดก่อนเทียบ; fit บนเที่ยวบินเดียว = calibration
3. **เที่ยวบินในตัวคง bit-for-bit บนเครื่องที่ปัก** — Node 22 ปักใน engines/.nvmrc/CI; hash 48 ตัวยังเป็น gate; tolerance tier (1 m, 1 mm/s, 1 step) เป็น *oracle* สำหรับ T02 และการย้าย Node ในอนาคต; บันทึกใหม่เฉพาะการเปลี่ยนที่ตั้งใจ พร้อมเหตุผลข้าง golden และใน VALIDATION §9 (แบบ F11) — ไม่มีวันเพื่อให้ CI เขียว
4. **ทุกสิ่งที่ผู้ใช้สร้างเป็นไฟล์ก่อน** — ผลลัพธ์, สมุด, สถานการณ์, แบบยาน, backup: JSON มี format/version/checksum เปิดออฟไลน์ได้ บินซ้ำได้; ไม่มีบัญชี เซิร์ฟเวอร์ analytics (PDPA, ผู้เยาว์, เครือข่ายปิด)
5. **ออฟไลน์คือผลิตภัณฑ์** — code-splitting ไม่ทำให้ออฟไลน์แย่ลง; precache ครอบทุก chunk; เฉพาะสื่อ (เสียง ภาพ landing) on-demand; precache *หด* ไม่โต โดยไม่มีเหตุวัดได้
6. **การ์ดคือเทสต์ใน repo ไม่ใช่ความจำ** — import boundary, ขนาดโมดูล, งบบันเดิล, i18n parity + deny-list ศัพท์, fingerprint, สุขอนามัย repo, ตัวเลขในเอกสาร — ทุกอันล้มภายใน ~10 นาที
7. **หนึ่ง session = หนึ่ง branch = หนึ่ง PR = หนึ่งเกณฑ์เสร็จ** — และ *ชั่วโมงของเจ้าของ* เป็นทรัพยากรที่ขาดแคลนที่สุด: AI session ทำได้เอง (docs, tests, CSS, ข้อมูลที่มีแหล่ง); เจ้าของต้องอ่านเอง (`src/physics`, `src/data`, สำเนาไทย, การตัดสินใจ); PR ที่ตามหลัง main >14 วันถูกปิดและเก็บ notes
8. **เนื้อหาโตด้วยไฟล์ โค้ดโตด้วย PR** — แพ็กบทเรียน, กรณีศึกษา, คำแปล มาเป็น `.orbitlab-lesson.json`/DOCX ที่สคริปต์ lint; เฉพาะเจ้าของ merge โค้ด
9. **glossary ตัดสินทุกคำ** — ไทยสำหรับครู อังกฤษสำหรับวิศวกรรม รัสเซียเมื่อสัญกรณ์ต่าง (ГОСТ 20058-80); guidance = การนำวิถี, navigation = การนำร่อง (D5); เทสต์ห้ามคำพ้องที่ถูกปฏิเสธ; ชื่อเฉพาะไม่แปล; ไม่แปลเอกสารวิศวกรรมยาวทั้งฉบับ
10. **เนื้อหาทหาร/ความมั่นคงจากแหล่งสาธารณะเท่านั้น** — อ้างอิงบนจอเดียวกับตัวเลข, *ผลที่ตามมา* ไม่ใช่ *ปฏิบัติการ*, DOP เป็น geometry ไม่จำลองสัญญาณ, ไม่มี Space-Track; **ไม่ใช้ชื่อ/ตราของ ทอ. หรือสถาบันโดยไม่มีอนุญาตเป็นลายลักษณ์อักษร**
11. **ป้ายซื่อตรง** — "experimental", "estimate", "planned vs flown", "ไม่ให้เกรด", บรรยากาศที่ใช้, tolerance ของโมเดล — มองเห็นตรงที่ตัวเลขแสดง และเทสต์นับให้ตรงกับ Known limitations
12. **การเปลี่ยน UI เป็น CSS/route-first และไม่ refactor main.ts/panel.ts ขณะมี feature branch เปิด** — refactor โดย extraction หลัง fitness function ในหน้าต่างสองสัปดาห์ที่ประกาศ; ไม่มี framework, ไม่มี runtime dependency ใหม่ (three.js ยังเป็นตัวเดียว)

### 7.2 ผลิตภัณฑ์, UX และการมีส่วนร่วม (product)

**การวินิจฉัย** — Orbitlab มีความลึกระดับห้องปฏิบัติการมหาวิทยาลัยอยู่หลัง *ทางเข้าของเดโม*: ต่ำกว่า 480 px ชื่อระดับทุกตัวถูกซ่อน (`modes.css`), ไม่มีกฎ `:lang(th)` ทำให้สระ/วรรณยุกต์ไทยถูกตัดด้วย line-height 1.3–1.45 ของ DM Sans เมื่อใช้ฟอนต์ระบบออฟไลน์, แท็บ `.pg-tabs` เลื่อนได้แต่ไม่มีสัญญาณบอก, การ์ดผลลัพธ์บอกสาเหตุแบบสำเร็จรูป, index 2.48 MB + i18n 1.1 MB + precache 16 MB (mp3 3.5 MB) แบบ atomic, `frame()` วาดทุก rAF แม้หยุดอยู่ — ทั้งหมดบนอุปกรณ์ที่ผู้ชมหลักมีจริงคือ Android ระดับกลางและ PC ห้องแล็บไม่มี GPU

**หลักการเฉพาะด้าน** — เริ่มด้วยงาน ไม่ใช่ทัวร์ (ทุกทางเข้าถึงสถานะ "กำลังทำ" ในหนึ่งแตะ ไม่บังคับ placement); หนึ่งการตัดสินใจต่อจอบนโทรศัพท์ (ต่ำกว่า 860 px แสดงงานเดียว: ตั้งค่า/ภาพ/ผล; เดสก์ท็อปไม่เปลี่ยน ไม่มีอะไรหลัง drawer ตามกฎเจ้าของ); ทุกผลลัพธ์บอก *ทำไม* และเสนอ *การทดลองถัดไปหนึ่งอย่าง*; การมีส่วนร่วมมาจากการทดลองและบริบทไทยบนฟิสิกส์ที่ validate แล้ว (ชั้นที่อ่านผล ไม่แก้ guidance/verdict/เกรด); วัดด้วยนาฬิกาจับเวลาและผู้ใช้ 5–6 คน ไม่ใช่ analytics; ออฟไลน์และเครื่องอ่อนก่อน (รับที่ 390×844 ไทย/รัสเซีย, CPU ช้า 4×, ไม่มี GPU; precache หดไม่โต); หนึ่ง PR ต่อการเปลี่ยนพร้อม journey ที่ล้มเมื่อ UX ถอย; ทดสอบผู้ใช้เป็นประตูของการขยาย
