# Changelog

All notable changes to Orbitlab are recorded here, newest first, one line per
merged pull request. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Orbitlab has no tagged release yet.

## Unreleased

- Lessons (FX-2 PR1, M-LEARNING-001): while a design lesson's check runs, the answer you are typing keeps its field, focus and caret — the progress figure is now written in place instead of rebuilding the strip about 100 times a check, and screen readers hear it in 10 % steps.
- FX-1 s2 (M-BUILD-006; owner, 2026-10-06, option b): a rocket design saved before FX-1 PR1 has its payload ratings computed again when it is opened in Build (in the background, with the usual progress line and Stop), since they may be a cut-off figure; a finished search replaces them without counting as a design edit (D-75), and one that does not finish changes nothing and is tried again next time.
- FX-8 (M-PLAN-019, KPI-15): when the browser loses the GPU context, Launch, Orbit and Home accept the loss so the browser can give it back, show a short status line (TH/EN/RU), and keep the mission clock and the recording running; on restore each 3-D view draws again as before — the launch scene re-renders its sky tables, environment probe and shadow map, and every view gets its background colour back. New browser journey `fx8-context-loss`.
- FX-1 PR1 (M-BUILD-006, D-67): Build computes payload ratings with a 40-flight limit and no time limit, so a slow device gets the same ratings instead of a cut-off lower figure (which Launch read as "cannot fly"); a search that did not finish is never kept as the rating, and without a worker the search now shows its progress and can be stopped.
- Storage (R1.6 PR1): a damaged learner profile no longer keeps its lock and leaves other tabs read-only; a failed clean-up at start (an interrupted profile deletion or an unreadable old record) no longer puts every profile into visit-only mode, it is retried at the next start with a notice; and typing in a number box still works after 1,000 boxes are remembered (the oldest is forgotten instead).

- Tests: the PR smoke check's phone step (`r2-shell-smoke`) no longer fails now and then on CI's slow software renderer. Its wait for a paused flight now reads the flight after the app has drawn a frame, so the event bar on screen matches what it reads; before, a frame drawn between the check and the tap could move the cluster chip from under the finger. A new smoke journey (`r2-chooser-late-frame`) reproduces that frame on purpose. App unchanged.
- Launch (FX-5, M-LAUNCH-029): in a replay, the Compare table's "This flight" column now shows the flight at the timeline cursor and changes as you scrub, like the HUD and the telemetry charts; it used to show the live run's latest figures. During the live flight the table is unchanged.

Soyuz-2.1a flies two payload sections: the cargo one (11S517A2, 3.0 m, fairing at T+183.2 s, the Progress cyclogram) for every payload but a crew, and the crewed one (11S517A3, 3.0 m under the escape tower, fairing at T+153.3 s) for a crew; both replace the commercial flights' 4.11 m fairing. The fairing-fit estimate reads the payload section a satellite flies in (the Soyuz MS is "tight" in its 3.0 m one, as Vostok in its shroud), and a custom satellite keeps a cargo ship's flight only as a copy of one.
